# Karvinen 2025: Wireshark – Getting Started

* Wireshark on verkkoliikenteen analysointiin tarkoitettu ohjelma, jolla voidaan kaapata ja tutkia verkkopaketteja.

* Wiresharkilla voidaan tarkastella verkkoliikennettä eri verkkoliitännöistä sekä tallentaa kaappauksia myöhempää analysointia varten.

* Ohjelmassa voidaan käyttää erilaisia suodattimia, kuten dns, tls ja http, joiden avulla voidaan tarkastella tiettyjä protokollia.

# Karvinen 2025: Network Interface Names on Linux

* Linuxissa verkkoliitännät voivat olla fyysisiä tai virtuaalisia. Esimerkiksi loopback liitäntää käytetään tietokoneen sisäiseen verkkoliikenteeseen.

* Verkkoliitännän nimen alkuosa kertoo yhteyden tyypin. en tarkoittaa kiinteää Ethernet yhteyttä, wl langatonta Wi-Fi-yhteyttä ja lo loopback-liitäntää.

* Omia verkkoliitäntöjä voidaan tarkastella komennolla ip a ja reititystietoja komennolla ip route

#  b) Ei voi kalastaa

Aloitin testaamalla internetyhteyttä Kali Linuxissa komennolla:

    ping 8.8.8.8

Samalla seurasin verkkoliikennettä Wiresharkilla ja huomasin, että ICMP-paketteja alkoi kulkea.

Seuraavaksi katkaisin verkkoyhteyden komennolla: ( Lähde: https://www.hakatemia.fi/courses/linux-hallinta-ja-koventaminen/verkko-asetukset-linux-ympaeristoessae )

    sudo ip link set dev eth0 down

Komento poisti eth0 verkkoliitännän käytöstä, jolloin internetyhteys katkesi ja ping pakettien kulku loppui Wiresharkissa.

Lopuksi otin verkkoliitännän takaisin käyttöön komennolla:

    sudo ip link set dev eth0 up

Tällä komennolla verkkoyhteyden sai jälleen käyttöön.

Wiresharkissa näkyi, että viimeinen ICMP paketti ennen yhteyden katkeamista oli rivillä 36. Tämän jälkeen verkkoliikenteessä oli noin 53 sekunnin tauko.

Kun otin eth0 verkkoliitännän takaisin käyttöön, Wiresharkissa näkyi rivillä 37 DHCP Request paketti ja rivillä 38 DHCP ACK vastaus, jonka avulla IP-osoite vahvistettiin.

# e) Mitäs tuli surffattua?

Avasin tehtävän mukana tulleen surfing-secure.pcap-tiedoston Wiresharkissa ja tutkin kaapattua verkkoliikennettä.

Kaappauksessa oli yhteensä 283 pakettia ja sen kesto oli noin 7,54 sekuntia. Tiedoston koko oli noin 127 kt.

Kaappauksessa esiintyi esimerkiksi TCP-, UDP-, DNS- ja TLS-protokollia. Suurin osa paketeista oli TCP-liikennettä.

DNS kyselyistä löytyi esimerkiksi verkkotunnukset www.terokarvinen.com ja www.google.com.


# f) Mitä selainta käyttäjä käyttää?

Käytin apuna ohjeita mitkä oli laitettu ja yritin selvittää, mitä selainta käyttäjä oli käyttänyt.

Avasin surfing-secure.pcap-tiedoston Wiresharkissa ja etsin TLS Client Hello paketteja suodattimella:

    tls.handshake.type == 1

Tutkin pakettien tietoja ja löysin kaksi erilaista JA3-sormenjälkeä:

1.   b5001237acdf006056b409cc433726b0

2.   a195b9c006fcb23ab9a2343b0871e362

Hain molempia sormenjälkiä JA3.ZONE palvelusta selvittääkseni, mitä selainta käyttäjä mahdollisesti käytti.

Ensimmäinen sormenjälki viittasi Firefox selaimeen. Toisen sormenjäljen tuloksissa näkyivät sekä Firefox että Chrome.

# g) Minkä merkkinen verkkokortti käyttäjällä on?

Avasin surfing-secure.pcap-tiedoston Wiresharkissa ja tutkin Ethernet II -tietoja.

Löysin MAC-osoitteet:

    52:54:00:cc:d7:12

    52:54:00:2f:e1:e5

Hain MAC-osoitteiden alkuosaa 52:54:00 MACLookup-palvelusta. Palvelu ei löytänyt rekisteröityä valmistajaa, mutta Wiresharkin tiedoissa mainittiin Realtek.

Selvitin myös, että samaa MAC-osoitteen alkuosaa käytetään QEMU-virtuaalikoneissa.

Tämän perusteella kyseessä on mahdollisesti virtuaalinen verkkokortti. Fyysisen verkkokortin valmistajaa en pystynyt varmistamaan.

# h) Millä weppipalvelimella käyttäjä on surffaillut?

Etsin TLS Client Hello paketteja suodattimella:
